# 리하원 근무표 및 송영관리 프로그램

리하원 재가노인복지센터의 월간 근무표 작성과 송영관리 연동을 위한 정적 웹 프로그램입니다.

## 작업 기준

이 저장소가 근무표와 송영표를 함께 관리하는 정본 프로젝트입니다.

- 근무표와 송영표를 함께 수정할 때는 이 폴더에서 작업합니다.
- Git 커밋과 배포도 이 폴더 기준으로 진행합니다.
- 바깥의 `송영 프로그램 ver1.0/송영관리프로그램.html` 단독 파일은 확인용 또는 이전 작업본으로 보고, 연결 기능이 필요한 수정은 이 저장소 안에서 진행합니다.

## 페이지 구성

- `/` : 근무표 작성 프로그램
- `/transport` : 송영관리 프로그램

## 주요 파일

- `index.html` : 메인 근무표 작성 프로그램입니다. 송영관리로 이동하는 버튼과 연결 데이터 생성 로직이 있습니다.
- `transport/index.html` : 실제 배포되는 송영관리 프로그램입니다. 근무표에서 넘긴 운전원/근무표 데이터를 받아 송영표 작성에 사용합니다.
- `수급자목록데이터.js` : 메인 근무표에서 함께 쓰는 수급자 데이터입니다.
- `transport/수급자목록데이터.js` : 송영관리 화면에서 직접 읽는 수급자 데이터입니다.
- `송영 프로그램 ver1.0/송영관리프로그램.html` : 송영관리 원본 보관용 파일입니다. `transport/index.html`과 같은 변경이 필요한 경우 두 파일을 같이 확인합니다.
- `송영 프로그램 ver1.0/수급자목록데이터.js` : 송영관리 원본 보관용 수급자 데이터입니다.

## 연결 방식

근무표에서 송영관리로 이동할 때 `index.html`이 운전 가능 직원과 월별 근무코드를 `localStorage` 및 URL 파라미터로 전달합니다. 송영관리의 `transport/index.html`은 이 데이터를 읽어 차량/운전원 배정과 송영표 작성에 사용합니다.

따라서 연결 동작을 확인할 때는 파일을 직접 여는 것보다 로컬 서버로 실행하는 것이 좋습니다.

```bash
cd "/Users/udcares/projects/hayashiokada-stack-rihawon-schedule"
python3 -m http.server 8080
```

- 근무표: `http://localhost:8080/`
- 송영관리: `http://localhost:8080/transport/`

## 수정 원칙

- 근무표 연결 기능은 `index.html`과 `transport/index.html`을 함께 확인합니다.
- 송영관리 화면만 고칠 때도 배포 기준 파일은 `transport/index.html`입니다.
- 수급자 데이터 변경은 세 파일을 같은 기준으로 맞춥니다.
  - `수급자목록데이터.js`
  - `transport/수급자목록데이터.js`
  - `송영 프로그램 ver1.0/수급자목록데이터.js`
- 토요일 서비스처럼 이용 요일 정책이 바뀌면 `clientsForDate`, 월 통계, 엑셀 가져오기/템플릿, 수급자 데이터 버전을 함께 확인합니다.

## 클라우드 동기화 (Firebase)

`firebase-config.js`에 Firebase 웹 설정값을 넣으면 **로그인(센터 공용 계정) + 클라우드 저장·공유**가 켜집니다.
설정 전에는 기존처럼 브라우저 localStorage 전용으로 동작합니다(로그인 화면 없음).

- 저장 시 클라우드에 반영, 페이지를 열 때(월 전환 시) 최신본을 불러옵니다(비실시간).
- 근무표: `centers/{센터}/schedules/{연}_{월}`, 송영표: `centers/{센터}/transport/db` 문서에 저장.
- 공용 파일: `firebase-config.js`(설정값·자리표시자), `firebase-sync.js`(동기화 모듈, 두 페이지 공통).
- 상세 설정 절차와 Firestore 보안 규칙은 **`FIREBASE_SETUP.md`** 참고.
